# 实景拼贴·人物融合版

以用户原图为参考，生成一张**包含原图主要人物的完整拼贴作品**。脸部尽可能还原；人物、服装和场景共同融入设计。按最新用户要求选择处理方式，不把历史案例的像素保护要求强加到所有照片。

## 先确定保真要求

- **默认 integrated：自然融合、脸部尽量还原。** “尽可能还原”“像本人”“保留原貌”“其他部分融入”采用此方式。重点保持脸型、五官比例、表情、视线、可见特征和人物关系。可以让整体光色、画面颗粒与纸感统一，不能借机瘦脸、美颜、改变年龄或把真人改成通用插画脸。
- **source-face-harmonized：原脸五官 + 统一风格。** “脸部从原图回贴但要融入”“保留五官同时统一肤色、光线或纸感”采用此方式。先局部对齐原脸，再用频率分离保留源图高频细节，只让低频肤色与光线有限度地靠近完整设计稿。默认协调强度 0.32，上限 0.6；阅读 [harmonization.md](references/harmonization.md)。
- **source-face-exact：原脸不调色、核心像素严格保留。** 仅在用户明确要求“原像素不变”“零差异”或拒绝任何脸部调色时使用。它的风格统一主要靠周围画面适应原脸。阅读 [face-protection.md](references/face-protection.md) 与 [job-schema.md](references/job-schema.md)。
- 用户明确选定的模式持续有效，直到用户明确更改。本任务已经从 exact 放宽到 harmonized 时，后续采用 harmonized；不要再声称脸部原像素零差异。
- 如实说明处理：integrated 使用生成式编辑；harmonized 使用原脸细节和程序化低频光色协调；exact 的零差异只适用于实际校验过的核心区。

## 创作步骤

1. 查看原图与用户指出的旧成品，确认主要人物、表情、动作、人物关系、场景线索及需要改善的地方。使用原图或忠实缩小的原图作为生成参考。大图片可用 Sharp 制作可查看的预览，原图保持不变。
2. 阅读 [collage-design.md](references/collage-design.md)，将人物与场景一起设计。保留重要姿势和可辨识细节，服装色块可延伸为纸片、头发外围可转为墨线、场景轮廓可贯穿人物周围，避免整个人被照片边框包围。
3. 调用当前环境的图像生成工具，输入原图，要求输出**完整带人物的拼贴设计稿**。遵循 imagegen 技能。所有人物、身体、服装、场景在这一步共同处理。不得默认要求“只生成背景”“不要人物”“留空稍后贴人”。
4. 将生成稿与原图并排看。先检查脸部是否像本人、表情和动作是否正确，再检查人物和场景是否自然融合、文字是否准确。若两方面都达到用户要求，直接交付；不为跑检测或获得零差异数字额外重做。
5. 若脸部明显走样，先做一次聚焦修正。仍不够像且用户重视身份还原时，优先采用最小范围的 source-face-harmonized；只有明确要求原像素时采用 source-face-exact。两者都不能扩大为整个人物、整匹马或一大块背景。
6. 局部回贴后检查眼鼻嘴的身份特征、肤色与光向、发际线/耳侧/下颌接缝以及人物与画面的整体关系。harmonized 不运行零差异硬门槛；exact 必须执行严格像素验证。
7. 最多先做一张完整设计稿和一次针对实际问题的修正。仍有明显问题时说明未解决之处，不无上限生成候选或绕回“无人底板加整块照片”的流程。

## 背影、遮挡和批量

- **背影、远景、脸不可见：**不启动人脸回贴，不凭空补脸。保留身体姿势与朝向，人物可以和场景一起转译为摄影与插画相融的形式。
- **侧脸、墨镜、头盔、裁切：**保留原图可见特征与遮挡，不能因检测不完整就扩大保护到整个身体、马或背景。integrated 可以依靠视觉检查；两种 source-face 若无法可靠实现，应说明局部限制。
- 检测失败是检测结果，不等同于这张照片不能进行拼贴。
- 对批量任务，先选择一张能代表人物与场景关系的照片进行质量检查，再推广同一方向。出现相同贴片感时应修正策略，不重复制作整批无人背景。
- 用户仅要求检查或修技能时，先完成诊断和规则修正，可用一张代表图验证；不得宣称已重做全部旧图。

## 交付与检查

默认只提供成品、预览和简短说明。生成提示词与必要检查记录放在独立的 _过程 文件夹；仅在实际用了原脸回贴时保留对应遮罩、参数和验证报告。不要为 integrated 模式生成无意义的人脸锁定文件、参考黑底图和像素报告。

integrated 的检查记录使用 mode=integrated。harmonized 记录 `pixelVerification=not-applicable`、协调参数和视觉观察，不得写“原像素不变”。exact 的准确声明必须来自严格脚本的真实报告。三种模式都需要视觉检查，不能只凭 ready=true 判断作品好看。

## 运行环境

integrated 主要使用当前环境的图像生成工具与图片查看器。两种 source-face 使用 Python 3.12、Node.js 22+ 与固定依赖；环境缺失时先按 [setup.md](references/setup.md) 安装，再执行 [job-schema.md](references/job-schema.md)。Python 只定位；Node/Sharp 负责对齐、频率协调、合成与检查。

这是独立技能，非上游官方版本。实现来源见 [sources.md](references/sources.md)。
